# BATARA PARVIEW — WEBSITE DESIGN SKILL
## Anti AI-Slop / Minimalist Elegant Residential Design System

> Purpose: This skill guides Antigravity when designing, rebuilding, or refining the Batara Parview website. The goal is a minimalist, elegant, premium residential-property experience that feels intentionally art-directed — never like a generic AI-generated website template.

---

# 1. CORE DESIGN DIRECTION

The website should feel:

- Minimalist
- Elegant
- Warm
- Premium but approachable
- Architectural
- Calm
- Modern residential
- Editorial rather than dashboard-like
- Human-designed and intentional

The visual language should communicate:
**quality of the homes + trust + simplicity + comfort.**

DO NOT design it like:
- SaaS landing pages
- AI startup websites
- Generic real-estate templates
- Dashboard interfaces
- Crypto/fintech websites
- Over-designed marketing pages

The design must prioritize the property photography, typography, whitespace, and content hierarchy.

---

# 2. ABSOLUTE ANTI AI-SLOP RULES

These rules have priority over aesthetic experimentation.

## NEVER use decorative elements just because they are popular.

Avoid:
- Excessive gradients
- Glassmorphism
- Frosted glass panels
- Huge glowing blobs
- Random abstract 3D shapes
- Floating decorative circles
- Excessive shadows
- Neon colors
- Excessive pills
- Excessive rounded cards
- Huge text for no reason
- Excessive emojis
- Random line decorations
- Generic geometric patterns
- AI-looking illustrations
- Stock-looking fake lifestyle imagery
- Excessive floating UI
- Every section becoming a card
- Every component having a different radius
- Excessive animations
- Bouncy UI
- Unnecessary parallax
- Decorative elements that do not support the brand

If an element does not improve:
1. hierarchy,
2. usability,
3. storytelling,
4. brand identity, or
5. conversion,

remove it.

---

# 3. DESIGN PRINCIPLE: LESS, BUT BETTER

When deciding between two designs:

Prefer:
- one strong image over three mediocre images
- one strong CTA over multiple competing CTAs
- one accent color over many accent colors
- whitespace over decoration
- typography over graphical gimmicks
- hierarchy over visual noise
- subtle interaction over flashy animation
- real photography over generated decorative visuals

Do not fill empty space simply because it looks empty.

Whitespace is intentional.

---

# 4. BRAND COLOR SYSTEM

Use a restrained palette inspired by the existing Batara Parview identity.

Primary:
- Deep forest green / dark botanical green
- Warm white / ivory
- Soft neutral gray
- Muted olive green

Accent:
- Natural green for active states and important CTAs
- Warm gold may be used sparingly for premium accents or brand details

Avoid:
- Bright neon green
- Multiple unrelated greens
- Pure black as the dominant visual color
- Excessive saturated colors
- Red unless specifically required by the brand/content

Recommended visual ratio:
- 70–80% neutral / warm white
- 15–25% dark green / typography
- 5% accent color

Color should feel quiet and premium.

---

# 5. TYPOGRAPHY

Typography is a major part of the visual identity.

Use a maximum of 2 font families.

Recommended combination:
- Elegant serif for selected editorial/display moments
- Clean modern sans-serif for UI and body copy

Alternative:
- One excellent sans-serif family with multiple weights.

Rules:
- Do not use excessive font weights.
- Do not make every heading huge.
- Do not use all-caps everywhere.
- Do not use overly futuristic fonts.
- Do not use generic "tech" typography.
- Maintain generous line-height.
- Use typography to create hierarchy rather than decoration.

Suggested hierarchy:

Display:
Large, restrained, editorial.

H1:
Strong but not oversized.

H2:
Clear section heading.

Body:
Comfortable reading size.

Metadata:
Small, quiet, secondary.

Price:
Strong visual priority.

CTA:
Medium weight, clear and confident.

---

# 6. LAYOUT SYSTEM

Use a consistent grid.

Desktop:
- Max content width approximately 1200–1400px depending on section.
- Generous horizontal margins.
- 12-column grid when useful.
- Consistent gutters.
- Avoid content touching viewport edges.

Tablet:
- Reduce columns intentionally.
- Preserve whitespace.
- Do not simply shrink desktop.

Mobile:
- Single-column priority layout.
- Maintain comfortable side padding.
- Keep primary CTA accessible.
- Avoid horizontal overflow.
- Cards should not become cramped.

The page should breathe.

Do not stack every element tightly.

---

# 7. NAVIGATION

The navbar should be quiet and premium.

Preferred structure:
- Logo on the left
- Small number of navigation items
- One primary contact CTA
- Clear active state

Avoid:
- Huge navbar
- Excessive buttons
- Multiple colored pills
- Heavy shadows
- Unnecessary icons
- Excessive rounded containers

Active navigation should be communicated subtly through:
- typography weight,
- underline,
- small accent indicator,
or another restrained treatment.

---

# 8. HERO SECTION

The hero is the first impression.

Do not use a busy full-screen background unless the photography genuinely supports it.

Preferred:
- Large architectural image
- Strong composition
- Plenty of negative space
- Short headline
- Short supporting copy
- One primary CTA
- Optional understated secondary action

The property should feel like the hero — not the UI.

Avoid:
- Huge gradient overlays
- Excessive text
- 5+ floating badges
- Random statistics
- Decorative blobs
- Multiple competing buttons

---

# 9. PROPERTY / TYPE RUMAH SECTION

This is a core product section.

The property cards should feel like premium editorial property listings, not ecommerce cards.

## Image

Photography should dominate the card.

Rules:
- Use large image area.
- Preserve image quality.
- Use consistent aspect ratio.
- Avoid unnecessary overlays.
- Avoid putting many badges on top of the photo.

Only show metadata that is genuinely useful.

## Property card

Recommended structure:

IMAGE
↓
Property name + category
↓
Short essential features
↓
Price
↓
Primary CTA / detail action

Do not create a UI chip for every piece of information.

Instead of:

[🚗 Carport] [🛏 2 Kamar] [🚿 1 Kamar Mandi]
[🛋 1 Ruang Tamu] [🌳 Taman]

prefer a clean metadata row/grid with small typography and restrained separators/icons.

---

# 10. BADGES

Badges are useful only when they communicate meaningful information.

Good examples:
- Subsidi FLPP
- Tipe 30/60
- Featured
- New

Bad examples:
- Random marketing slogans
- Decorative labels
- Multiple badges saying similar things
- Emoji-heavy labels

Maximum:
- 1–2 meaningful badges per property card.

---

# 11. FILTERS

Property filters should be simple.

Preferred:
- Text-based tabs
- Minimal segmented control
- Underline active state
- Soft neutral container if necessary

Avoid:
- Large colorful pill collections
- Excessive icons
- Emoji-heavy filters
- Every filter looking like a CTA

The active filter should be obvious but restrained.

---

# 12. PROPERTY INFORMATION

Prioritize:

1. Property name
2. Property type
3. Important specifications
4. Price
5. Financing/installment information
6. Action

Do not give equal visual weight to everything.

Example hierarchy:

Kalmia
Tipe 30/60

2 Kamar Tidur · 1 Kamar Mandi · 1 Ruang Tamu

Rp 185 Juta
Mulai dari Rp 1,1 Jt/bulan

[Tanya Unit]

The price should be easy to find without dominating the whole card.

---

# 13. CTA SYSTEM

Have one clear primary action.

Preferred CTA language:
- Tanya Unit
- Lihat Detail
- Hubungi Kami
- Konsultasi

Primary CTA:
- Solid dark green or controlled brand accent.
- Strong contrast.
- Moderate radius.
- No excessive glow.

Secondary action:
- Outline or text button.
- Visually quieter.

Do not make every button green.

If everything is emphasized, nothing is emphasized.

---

# 14. FLOATING PROMO / WHATSAPP

Floating elements must not dominate the interface.

The current promo button and WhatsApp widget should be visually reduced.

Rules:
- Keep them compact.
- Do not cover important content.
- Avoid oversized capsules.
- Avoid excessive animation.
- Use a subtle entrance animation.
- Ensure mobile usability.
- Maintain sufficient distance from screen edges.

The property content remains the priority.

---

# 15. CARDS

Cards should not all look like floating rounded rectangles.

Use cards only when they help group information.

Preferred:
- Moderate radius
- Thin border
- Very subtle shadow or no shadow
- Strong internal spacing
- Clean typography

Avoid:
- Giant radius
- Heavy shadow
- Multiple nested cards
- Card inside card inside card
- Every section floating independently

Use flat editorial layouts where appropriate.

---

# 16. BORDER RADIUS

Use a small, consistent radius system.

Suggested:
- Small: 8px
- Medium: 12px
- Large: 16px
- Very large radius only for major visual containers

Do not use 30–50px radius everywhere.

Avoid making the entire website look like a collection of inflated capsules.

---

# 17. SHADOWS

Shadows should communicate elevation, not decoration.

Prefer:
- Very subtle shadow
- Soft low-opacity shadow
- Border instead of shadow when possible

Avoid:
- Heavy black shadows
- Large blurry shadows
- Multiple shadow layers
- Glowing cards

Premium design is often flatter than AI-generated design.

---

# 18. ICONS

Use icons sparingly.

Preferred:
- Simple line icons
- Consistent icon family
- Small size
- Neutral color

Avoid:
- Emoji as the primary UI icon system
- Mixing many icon styles
- Giant icons
- Icons on every sentence

If an icon does not improve recognition, remove it.

---

# 19. IMAGERY

Architecture photography is the hero of the website.

Use:
- Real property images
- Consistent crop
- Natural lighting
- Clean compositions
- High-quality imagery

Do not:
- Over-process images
- Add artificial glow
- Add random decorative overlays
- Use fake AI-generated architecture if real photography exists
- Crop important architectural details unnecessarily

Image treatment should feel like an architectural property brochure.

---

# 20. SECTION DESIGN

Every section should have a clear purpose.

A good section has:
- clear heading
- supporting context
- content
- intentional spacing

Do not create sections simply to make the page longer.

Avoid repetitive structures such as:

Heading
3 cards
Heading
3 cards
Heading
3 cards

Instead vary composition:
- editorial split layout
- large image + text
- asymmetric grid
- full-width photography
- simple content block
- comparison layout
- property showcase

But variation must remain within the same design system.

---

# 21. VISUAL RHYTHM

The page should have a deliberate rhythm:

Large visual
→ breathing space
→ information
→ breathing space
→ next visual

Do not make every section equally dense.

Use changes in:
- scale
- whitespace
- image size
- typography
- alignment

to create hierarchy.

---

# 22. ANIMATION

Animation should feel expensive, not loud.

Use:
- subtle fade
- gentle slide
- image reveal
- smooth hover transition
- slight scale on image hover
- soft navigation transitions

Timing:
- generally 200–500ms for UI interactions
- slower for large editorial reveals

Avoid:
- bounce
- elastic effects
- excessive spinning
- constant floating
- aggressive parallax
- animations on every component

Motion should support attention, not compete for it.

---

# 23. HOVER STATES

Desktop hover states should be subtle.

Good:
- Image scale 1.02–1.04
- Slight shadow change
- Border change
- CTA transition
- Text color transition

Avoid:
- Large movement
- Rotation
- Glow
- Bounce
- Excessive transformation

---

# 24. RESPONSIVE DESIGN

Never treat mobile as a compressed desktop.

Desktop:
- generous grid
- larger imagery
- horizontal navigation

Mobile:
- compact navigation
- single-column property listings
- readable typography
- touch-friendly controls
- sticky or easily accessible primary CTA when appropriate

Do not allow:
- horizontal scroll
- clipped text
- tiny buttons
- overlapping floating widgets
- oversized hero headings

---

# 25. ACCESSIBILITY

Maintain:
- sufficient color contrast
- readable font sizes
- clear focus states
- semantic HTML
- meaningful button labels
- alt text for important images
- keyboard navigation

Do not sacrifice usability for aesthetics.

---

# 26. CONTENT DENSITY

Do not overcrowd.

If a card feels crowded:
1. remove non-essential content,
2. reduce visual decoration,
3. improve spacing,
4. combine related information,
5. then reconsider typography.

Do NOT solve overcrowding by making text smaller.

---

# 27. ANTI-TEMPLATE TEST

Before considering the design finished, ask:

"Could this website be mistaken for a generic AI-generated SaaS template?"

If YES:
- remove unnecessary pills
- remove unnecessary gradients
- remove unnecessary cards
- simplify colors
- improve typography
- increase whitespace
- strengthen image art direction
- create a more distinctive composition

Ask:

"Does this look like a real property brand with a specific visual identity?"

If NO:
- improve brand-specific visual decisions.

---

For the current Batara Parview interface:

---

# 29. IMPLEMENTATION PRIORITY

When modifying an existing website, do NOT rewrite everything immediately.

Follow this order:

1. Preserve existing functionality.
2. Preserve existing content and property data.
3. Preserve working navigation.
4. Establish design tokens.
5. Fix global typography.
6. Fix spacing/grid.
7. Simplify navbar.
8. Simplify hero.
9. Redesign property cards.
10. Simplify filters.
11. Simplify CTAs.
12. Reduce floating UI.
13. Add subtle interaction.
14. Test responsive layouts.
15. Check accessibility.
16. Remove unnecessary decoration.

Do not break existing functionality merely to achieve visual changes.

---

# 30. DESIGN TOKENS

Create reusable variables instead of hardcoding random values.

Example:

--color-bg: warm neutral
--color-surface: white
--color-text: deep green
--color-text-muted: neutral gray
--color-primary: restrained green
--color-border: soft neutral

--radius-sm: 8px
--radius-md: 12px
--radius-lg: 16px

--space-xs: 4px
--space-sm: 8px
--space-md: 16px
--space-lg: 24px
--space-xl: 40px
--space-2xl: 64px
--space-3xl: 96px

Use a consistent spacing scale.

---

# 31. CODE QUALITY

Design quality must be reflected in implementation.

Use:
- semantic HTML
- reusable components
- CSS variables/design tokens
- consistent class naming
- responsive CSS
- clean component structure

Avoid:
- duplicated styles
- random inline styles
- arbitrary pixel values everywhere
- unnecessary dependencies
- unnecessary JavaScript for simple UI
- excessive absolute positioning

If an effect can be achieved cleanly with CSS, prefer CSS.

---

# 32. DO NOT INVENT DESIGN DETAILS

When a reference, logo, image, or brand asset exists:
- respect it
- do not replace it with a generic alternative
- do not change brand identity without instruction

When information is unknown:
- use a restrained neutral solution
- do not invent decorative content

---

# 33. FINAL QUALITY CHECK

Before delivering the website, verify:

[ ] Does it look intentionally designed?
[ ] Does it avoid generic AI aesthetics?
[ ] Is whitespace generous?
[ ] Is typography strong?
[ ] Is the property photography the visual priority?
[ ] Are there too many pills?
[ ] Are there too many badges?
[ ] Are there too many cards?
[ ] Are colors restrained?
[ ] Are shadows subtle?
[ ] Are border radii consistent?
[ ] Is the CTA hierarchy obvious?
[ ] Is the page easy to scan?
[ ] Does mobile look intentionally designed?
[ ] Are animations subtle?
[ ] Is the interface accessible?
[ ] Did functionality remain intact?

If several answers are NO, refine the design before finishing.

---

# 34. MOST IMPORTANT RULE

Do not try to make the website look "fancy."

Make it look **intentional**.

The goal is not to demonstrate how many visual effects can be generated.

The goal is to create a website that looks like a professional designer carefully made every decision.

**Minimal does not mean empty.**
**Premium does not mean flashy.**
**Modern does not mean AI-generated.**
**Elegant comes from restraint, hierarchy, typography, composition, and consistency.**
